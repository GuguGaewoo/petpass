# 배포

웹은 Vercel, 백엔드는 Render 를 쓴다. 데이터는 Supabase 에 있고 배포와 무관하다.

```
사용자 → Vercel (Flutter Web)
           ├─ Supabase        전체 장소 목록
           └─ Render          상세 진입 시 Open API 실시간 확인
```

---

## 1. Vercel 배포

### 사전 준비

- Vercel 계정 ([vercel.com](https://vercel.com) → GitHub 으로 가입)
- 배포할 브랜치가 GitHub 에 올라가 있을 것

### 프로젝트 생성

1. Vercel → **Add New → Project**
2. `GuguGaewoo/petpass` 선택 → Import
3. **Root Directory 는 그대로 둔다** (저장소 루트). `app/` 으로 바꾸지 않는다.
   `vercel.json` 이 루트에 있고 빌드 스크립트가 `app/` 으로 들어간다.
4. Framework Preset: **Other**
5. Build/Output 설정은 건드리지 않는다. `vercel.json` 이 지정한다.

| 항목 | 값 | 출처 |
|---|---|---|
| Build Command | `bash scripts/vercel_build.sh` | vercel.json |
| Output Directory | `app/build/web` | vercel.json |
| Install Command | `echo skip` | vercel.json |

### 환경변수 등록

Settings → **Environment Variables** 에 4개를 넣는다.
Production / Preview / Development 모두 체크한다.

```
NAVER_MAP_CLIENT_ID       네이버 클라우드 Client ID
SUPABASE_URL              https://opawzxypkyvpqqimqnla.supabase.co
SUPABASE_PUBLISHABLE_KEY  Supabase Publishable(anon) 키
PETPASS_API_BASE_URL      https://petpass-api-gpex.onrender.com
```

**절대 등록하지 않는 것**

```
SUPABASE_SERVICE_KEY   RLS 를 우회하는 관리자 키
TOUR_API_KEY           Open API 인증키
```

`--dart-define` 으로 넘긴 값은 빌드 산출물에 그대로 박힌다. 위 두 개가
들어가면 누구나 꺼내 쓸 수 있다. 빌드 스크립트가 이 둘이 있으면
배포를 중단시키지만, 애초에 넣지 않는 것이 맞다.

### 배포

**Deploy** 를 누른다. Flutter SDK 를 내려받으므로 첫 빌드는 5~10분 걸린다.

빌드 로그에서 이 두 줄을 확인한다.

```
✓ NAVER_MAP_CLIENT_ID
✓ SUPABASE_URL
✓ SUPABASE_PUBLISHABLE_KEY
✓ PETPASS_API_BASE_URL
...
완료: app/build/web
```

## 2. 배포 후 반드시 할 것 (2가지)

이걸 안 하면 **배포는 성공하는데 지도와 실시간 조회가 동작하지 않는다.**
배포 주소를 `https://petpass-xxxx.vercel.app` 라고 하자.

### 2-1. Render — CORS 허용

Render → `petpass-api` → **Environment** → `ALLOWED_ORIGINS` 수정

```
http://localhost:8080,https://petpass-xxxx.vercel.app
```

- 콤마로 구분, **끝에 슬래시를 붙이지 않는다**
- 로컬 주소를 남겨야 개발 중에도 막히지 않는다
- 저장하면 자동 재배포된다

빠뜨리면 브라우저 콘솔에 CORS 오류가 나고 상세화면의 실시간 조회가
전부 실패한다. 앱은 폴백으로 계속 동작하므로 눈치채기 어렵다.

### 2-2. 네이버 클라우드 — 도메인 등록

콘솔 → Application → **Web 서비스 URL** 에 추가

```
http://localhost:8080
https://petpass-xxxx.vercel.app
```

빠뜨리면 지도 자리가 회색으로 남는다.

> 앱(APK)은 **Android 앱 패키지 이름** 에 `kr.petpass.petpass` 가
> 등록되어 있어야 한다. 웹 URL 과 별개다.

## 3. 배포 확인

브라우저에서 배포 주소를 열고 확인한다. **F12 콘솔을 함께 연다.**

| 확인 | 정상 |
|---|---|
| 장소 개수 | 632곳 |
| 탭 아이콘 | 발바닥 (Flutter 로고 아니어야 함) |
| 탭 제목 | PetPass |
| 상세 진입 | 즉시 열림 |
| 상세 지도 | 정상 표시 |
| 콘솔 | CORS 오류 없음 |

실시간 조회가 실제로 일어났는지는 Supabase SQL Editor 에서 본다.

```sql
select endpoint, content_id, caller, success, called_at
from kto_api_log
where caller = 'live'
order by called_at desc
limit 5;
```

방금 누른 장소의 `content_id` 가 찍혀 있어야 한다.
같은 장소를 10분 안에 다시 눌러도 로그가 늘지 않는 것이 정상이다(TTL).

## 4. 이후 배포

`develop` 에 push 하면 Vercel 이 자동으로 다시 빌드한다.

심사 제출 시점에는 `main` 으로 옮기는 것을 권한다. 작업 중 push 마다
재배포되면 그 사이 서비스가 잠깐 흔들린다.

```bash
git checkout main
git merge develop
git push origin main
```

Vercel → Settings → Git → Production Branch 를 `main` 으로 변경.
Render 도 같은 이유로 `main` 으로 바꾼다.

## 5. 문제가 생기면

**빌드가 환경변수 오류로 멈춤**
→ Vercel Settings → Environment Variables 확인. 등록 후 **Redeploy** 필요
   (환경변수만 저장해서는 재빌드되지 않는다)

**빌드는 됐는데 지도가 안 뜸**
→ 네이버 콘솔에 배포 주소가 등록되지 않았다 (2-2)

**상세 진입은 되는데 실시간 조회가 안 됨**
→ `ALLOWED_ORIGINS` 에 배포 주소가 없다 (2-1). 콘솔에 CORS 오류가 보인다

**첫 진입이 느림**
→ Render 무료 티어가 잠들어 있다. 화면은 즉시 열리고 "최신 정보 확인 중"
   표시만 몇 초 보인다. 정상 동작이다.
   심사 직전에는 Actions → Backend keep-alive → Run workflow 로 깨워둔다

**Flutter 버전 때문에 빌드 실패**
→ `scripts/vercel_build.sh` 의 `FLUTTER_VERSION` 을 로컬 `flutter --version`
   과 맞춘다

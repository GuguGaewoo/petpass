# 데이터 실사 기록

`pipeline/tour_probe.py profile` 출력을 그대로 붙여 기록한다.
설계 결정의 근거이며, 1차 심사 기능설명서 작성 시 인용한다.

---

## 확인된 사실 (2026-07)

- 엔드포인트: `KorPetTourService2` / `areaBasedList2` / `detailPetTour2`
  (버전 `2` 없는 경로는 404)
- 서울(areaCode=1) 총 **58건** → 전국 규모는 크지 않을 것으로 추정
- 상세 조회는 `contentId` 단건 조회만 지원 → 장소 수만큼 호출 필요
- 체중·견종 제한을 담는 **숫자 필드가 없음**. 자연어 파싱 필수

### 대표 사례 — 오인 위험

`그루브하우스` (contentid 3438659, 서울 동대문구)

```
acmpyTypeCd   : 전구역 동반가능
acmpyPsblCpam : 시각 장애인 안내견
acmpyNeedMtr  : 목줄 착용
```

동반 유형만 보면 가능처럼 읽히나 실제로는 안내견 전용.
지정과제 6번이 지적한 "모호한 출입 조건으로 인한 현장 입장 거부"가
공공데이터 자체에 그대로 드러난 사례.

## profile 출력

```
(python tour_probe.py profile 결과를 여기 붙여넣기)
```

### 여기서 읽어야 할 것

| 지표 | 왜 중요한가 | 결과 |
|---|---|---|
| 펫 필드 채움률 | 30% 미만이면 "정보없음"이 화면을 뒤덮음 → UX 재설계 | |
| `acmpyTypeCd` 고유값 수 | 판정 1차 기준 enum 확정 | |
| `acmpyPsblCpam` 고유값 수 | 20~30개면 규칙 기반, 수백 개면 LLM 정규화 필요 | |
| 오인 위험 케이스 건수 | 서비스 필요성의 정량적 근거 | |
| 체중 표현 비율 | `max_weight_kg` 실현 가능성 | |
| 견종 크기 표현 비율 | `size_restriction` 실현 가능성 | |

## 설계 결정

| 결정 | 근거 |
|---|---|
| 배치 수집 구조 채택 | 데이터 규모가 작고 갱신이 잦지 않음. 키 노출·CORS·트래픽 한도 동시 해결 |
| 판정을 4단계로 (정보없음 포함) | 채움률이 100%가 아니므로 모름을 정직하게 표시해야 함 |

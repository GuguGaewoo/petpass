## 신청 사유

```
본 서비스는 이용자가 입력한 반려견 정보(체중, 견종, 보조견 여부)를
기준으로 전국 632개 장소의 동반 가능 여부를 자동 판별하여
'가능 / 조건부 가능 / 불가'로 안내하는 서비스입니다.

실시간 호출 방식으로는 아래 두 가지 기능이 기술적으로 성립하지
않아 로컬 서버 저장 방식을 신청합니다.

1. 자연어 조건의 사전 구조화가 필요합니다

   반려동물 동반여행 정보의 동반 조건은 "9kg 이하 동반 가능",
   "맹견의 경우 입마개 착용 필수", "실내는 동반 불가" 와 같이
   자유 서술 형태로 제공됩니다.

   본 서비스는 이 문장에서 체중 상한, 견종 제한, 입마개 조건,
   동반 마릿수, 필요 준비물, 동반 불가 구역을 추출하여 구조화한 뒤
   이용자의 반려견 정보와 대조합니다. 이 추출 처리는 문장 단위 분석을
   수반하므로 이용자의 조회 시점마다 수행할 수 있는 성질이 아니며,
   사전에 처리한 결과를 보관해야 판별 기능이 성립합니다.

2. 조건 변경 시 전체 재판별이 필요합니다

   이용자가 반려견 정보를 변경하면(예: 체중 5kg → 20kg) 전체 장소의
   판별 결과가 즉시 달라져야 합니다. 동일 장소가 5kg 기준으로는
   '가능', 20kg 기준으로는 '불가'로 표시되기 때문입니다.

   또한 지역·유형·명칭 검색 시에도 전체 장소를 대상으로 조건을
   비교합니다. 이 과정을 실시간 호출로 처리하면 이용자의 조작 한 번에
   수백 회의 호출이 발생하며, 이는 응답 지연뿐 아니라 공사 서버에
   불필요한 부하를 유발합니다.

다만 저장한 정보만으로 서비스하지 않습니다. 이용자가 개별 장소의
상세정보를 조회하는 시점에는 해당 장소의 동반 조건을
반려동물 동반여행 정보(detailPetTour2)로 다시 호출하여 조회 시점의
정보를 기준으로 안내합니다. 저장 정보는 목록 조회와 사전 판별에
사용하고, 최종 확인은 실시간 호출로 수행하는 구조입니다.

원본 정보(개요, 홈페이지, 판정 근거 원문)는 수정하지 않고 원문
그대로 보존하며, 자체 분석 결과와 구분하여 저장·표시합니다.
이미지는 저장하지 않고 제공된 URL을 그대로 참조합니다.
```

## 동기화 계획

```
[동기화 대상]

  반려동물 동반여행 정보 — 장소 목록 및 동반 조건 상세
  국내관광정보(한국어)  — 장소 개요, 홈페이지, 대표이미지 URL,
                          주변 관광지 정보

[동기화 주기 및 시간]

  1일 1회, 매일 08:00 (KST)

  공사의 콘텐츠 동기화가 매일 새벽 04:30 과 07:30 두 차례 진행되는
  점을 고려하여, 두 시점을 모두 지난 08:00 으로 설정하였습니다.
  스케줄러로 자동 실행되며 수동 개입이 필요하지 않습니다.

[동기화 방법]

  1. 지역기반 관광정보 조회(areaBasedList2)로 전국 목록을 전수 조회

  2. 각 항목의 콘텐츠 수정일(modifiedtime)을 저장된 값과 비교

     - 수정일이 동일한 경우
       명칭·주소·좌표·연락처 등 목록 수준 정보만 갱신하고
       상세 조회는 수행하지 않습니다.

     - 수정일이 변경되었거나 신규 항목인 경우
       상세 조회(detailPetTour2)로 동반 조건을 재수집하고
       구조화 처리를 다시 수행합니다.

  3. 목록에서 확인되지 않는 항목은 삭제하지 않고 비활성 처리하여
     서비스 노출만 중단합니다.

  4. 조회 실패가 발생한 지역이 있는 경우, 해당 회차의 비활성 처리를
     수행하지 않습니다. 일시적 통신 오류를 '콘텐츠 삭제'로 오인하여
     정상 데이터가 서비스에서 누락되는 것을 방지하기 위함입니다.

[실시간 재확인 — 저장 정보에만 의존하지 않기 위한 절차]

  이용자가 개별 장소의 상세정보를 조회하는 시점에 해당 장소의
  동반 조건을 detailPetTour2로 다시 호출하여 판별에 반영합니다.
  동일 장소에 대한 중복 호출을 방지하기 위해 10분의 캐시 유효시간을
  적용합니다.

[동기화 이행 점검]

  모든 API 호출은 호출 시각, 기능명, 대상 콘텐츠 ID, 성공 여부를
  로그로 기록하여 동기화 이행 여부를 상시 확인할 수 있습니다.
  스케줄러 실행 이력으로도 정기 동기화 수행 여부를 확인할 수
  있습니다.

[예상 호출량]

  목록 조회  지역코드 기준 1일 약 40~80회
  상세 조회  수정일이 변경된 항목에 한하여 수행
  실시간     이용자의 상세 조회 시점에만 발생
```

## ⚠ 제출 전 확인할 것

### 1. 출처 표기 — 확인 필요

운영계정 승인 심사 기준 4번은 출처 표기를 요구합니다.

```
출처 : ⓒ한국관광공사    또는    ⓒ한국관광콘텐츠랩
(TourAPI 로 표기하지 말 것)
```

그런데 공모전 설명회에서는 서비스 내 공사 명칭 사용을 지양하라고
안내했습니다. 현재 서비스는 그에 따라 `출처 공공 관광데이터`로
표기하고 있어 위 기준과 어긋납니다.

**두 규정이 충돌하므로 운영팀에 직접 확인해야 합니다.** 신청서 제출
메일에 아래를 덧붙이는 것을 권합니다.

> 공모전 설명회에서 서비스 내 공사 명칭 사용을 지양하라는 안내를
> 받았습니다. 저작권 출처 표기(ⓒ한국관광공사)는 그와 별개로 표기해야
> 하는 것으로 이해하면 되는지 확인 부탁드립니다.

회신 전이라도 출처 표기를 넣는 편이 안전합니다. 출처 표기 누락은
저작권 문제이지만, 명칭 사용 제한은 공사 공식 서비스로 오인되는 것을
막기 위한 취지로 보이므로 출처 표기까지 금지하는 것은 아닐 가능성이
높습니다. 다만 이는 해석이므로 회신으로 확정해야 합니다.
